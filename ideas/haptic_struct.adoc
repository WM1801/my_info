## Архитектура системы управления

**Система делится на два уровня:**

- **Жесткий реальный контур** — управление приводами с детерминированной задержкой

- **Гибкий высокоуровневый контур** — пользовательская логика, интерфейс, сложные вычисления

```
 ---------------------------------------------------------------
│              ОДНОПЛАТНИК (Linux с RT-ядром)                 │
│                                                             │
│   ------------------------------------------------------    │
│  │  УРОВЕНЬ 1: ЖЕСТКИЙ РЕАЛ-ТАЙМ (1 кГц)              │   │
│  │   - Чтение данных с датчиков                       │   │
│  │   - Выполнение модели управления                   |   |
|  |      с учетом ДСП данных пользователя              │   │
│  │   - Отправка команд на приводы                     │   │
│  │   - Защита: если модель слишком медленная -> стоп   │   │
│   -------------------------------------------------------   |
│                         ▲ ▼                                │
│                    Обмен данными                           │
│                         ▲ ▼                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  УРОВЕНЬ 2: ГИБКАЯ ЛОГИКА (100 Гц)                  │   │
│  │  - Пользовательские алгоритмы                      │   │
│  │  - Веб-интерфейс или UDP обмен с внешним / клиентом                                   │   │
│  │  - Сложные вычисления           │   │
│  │  - Сетевое взаимодействие                          │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
              │
              │ EtherCAT 
              ▼
┌─────────────────────────────────────────────────────────────┐
│  ИСПОЛНИТЕЛЬНЫЕ УСТРОЙСТВА (N каналов)                      │
│  ├─ Канал 1: Датчик силы → Контроллер → Энкодер             │
│  ├─ Канал 2: Датчик силы → Контроллер → Энкодер             │
│  ├─ ...                                                     │
│  └─ Канал N: Датчик силы → Контроллер → Энкодер             │
└─────────────────────────────────────────────────────────────┘
```

## Преимущества

### В разработке
- Один одноплатник вместо связки "Linux + микроконтроллер"
- Нет необходимости в прошивке и перепрошивке, нет рисков "окирпичить" контроллер
- Стандартные инструменты разработки (GCC, GDB, MATLAB)
- Синхронизация всех устройств с высокой точностью
- Все каналы сидят на одном Ethercat, простота добавления новых каналов


### Для пользователя
- Пользователь редактирует только свою часть модели или реализует свою модель
- Изменения применяются без пересборки образа
- Можно использовать  MATLAB, C/C++, Python
- Возможность моделирования системы в MATLAB/Simulink

### Стабильность 
- Автоматическая проверка времени выполнения, уведомление об этом пользователя
- Аварийная остановка при превышении отведёного времени выполнения или других проблемах


---

### Поток данных (каждую миллисекунду):

```
1. Чтение данных
   ├─ Датчики силы → одноплатник
   ├─ Энкодеры положения → одноплатник
   └─ Статус приводов → одноплатник

2. Вычисления
   ├─ Пользовательская модель (редактируемая)
   ├─ Расчет управляющих воздействий
   └─ Проверка безопасности

3. Отправка команд
   ├─ Команды момента → приводы
   ├─ Команды положения → приводы
   └─ Команды управления → приводы

4. Параллельно (каждые 10 мс):
   ├─ Отправка телеметрии на веб-интерфейс
   ├─ Прием команд от пользователя
   └─ Логирование данных
```

## Слайд 5: Интеграция с MATLAB/Simulink

### Для разработчика модели

**Без перепрошивки:**
- Открываете модель в Simulink на своем компьютере
- Подключаетесь к работающей системе
- Меняете параметры (коэффициенты, настройки)
- Видите результат в реальном времени
- Применяете изменения мгновенно

**Автоматическая защита:**
- Система проверяет, не слишком ли сложная модель
- Если модель выполняется дольше 0.8 мс → предупреждение
- Если дольше 1 мс → аварийная остановка

### Пример использования

```
Разработчик → Simulink модель → Генерация C-кода → Загрузка на одноплатник
                    ↓
            Online-тюнинг параметров
                    ↓
            Мониторинг в реальном времени
```

## Слайд 6: Веб-интерфейс

### Что видит пользователь

**Мониторинг:**
- Графики положения, скорости, усилия в реальном времени
- Статус всех 7 каналов
- История данных

**Управление:**
- Слайдеры для изменения параметров
- Кнопки для переключения режимов
- Возможность загрузки пользовательских алгоритмов

**Доступ:**
- Через любой браузер (Chrome, Firefox)
- С любого устройства в сети (ПК, планшет, телефон)
- Не требует установки специального ПО

## Слайд 7: Масштабируемость

### Текущая конфигурация
- **7 каналов** исполнения
- **21 устройство** на шине EtherCAT
- **1 кГц** частота обновления
- **1 мс** цикл управления

### Возможности расширения
- До **50 каналов** на одной шине (при снижении частоты)
- До **100+ устройств** (датчики, приводы, I/O)
- Добавление новых типов устройств без изменения архитектуры
- Подключение нескольких шин EtherCAT для еще большей масштабируемости

## Слайд 9: Ключевые технические решения

### 1. Разделение на RT и non-RT процессы
- RT-процесс работает на изолированных ядрах процессора
- Non-RT процесс не влияет на стабильность управления
- Обмен данными через общую память без блокировок

### 2. Промышленная шина EtherCAT
- Все устройства синхронизированы с точностью < 1 мкс
- Один кадр данных проходит через все устройства
- Минимальная задержка от датчика до привода

### 3. Защита пользовательского кода
- Автоматическая проверка времени выполнения
- Ограничение ресурсов (память, CPU)
- Аварийная остановка при нарушениях

### 4. Веб-интерфейс без нагрузки на RT
- Данные передаются отдельным процессом
- RT-система не занимается сетью
- Веб-интерфейс может "лагать" без влияния на управление
